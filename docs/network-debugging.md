# 网络诊断使用说明

## 建议设置

打开 `Launch Custom.cmd`，按 F9 进入设置，选择 **网络**。

- **系统默认（推荐）**：沿用 Windows 的本地 Clash 代理，由 Clash 对当前 tailnet 与自建 Fever 精确域名直连，其他网站维持原规则。
- **直连**：整个 fork 的默认会话和文章沙箱都绕过显式 HTTP 代理；这不是“只让 RSS 直连”。仍可能受系统 TUN/路由影响。
- **PAC**：先在「应用偏好」填写 PAC 地址。空 PAC 会被拒绝，不会悄悄保存一个损坏的新模式。

页面显示的是 Chromium 的路由。例如 `PROXY 127.0.0.1:7897` 表示请求先进入本机 Clash，并不表示 Clash 最终用了海外节点；本轮配置会让内网 RSS 经绑定 Tailscale 网卡的 direct 出口访问。

## 添加服务前就能诊断

设置 → 服务 → Fever，填写端点、用户名、密码后，可先点 **诊断当前端点**，不必先保存账号。

- 诊断只发认证请求，不导入订阅、不推进文章游标、不标已读。
- HTTP 状态、认证、耗时、路由分别显示。HTTP200 但 `auth:0` 是“网络已到达、凭据被拒绝”，不是连接成功。
- HTTP502、坏 JSON、超时、网络失败分别归类；可提取时保留白名单内的 `net::ERR_*` 错误码，不记录异常原文。
- 普通 Fever 请求默认15秒超时；手动端点诊断请求默认8秒超时。

## 出错时的操作

1. 在网络页打开 **详细诊断**。
2. 返回 Fever 页，重现一次问题或点诊断。
3. 网络页点 **导出诊断**，选择本地日志文件。
4. 将日志交给维护者分析；完成后关闭详细诊断即可。

默认会保留脱敏的请求/同步/诊断摘要。详细模式增加结构化明细，不增加正文或凭据。日志文件为 `%APPDATA%/fluent-reader-custom/logs/network-diagnostics.log`，256KiB 轮转，保留一个 `.1` 备份；导出前再次脱敏。不要手工把账号配置 `config.json` 当日志分享。

## 保留与边界

- 原版程序、两个真实 profile 的账号/数据库均未迁移或重置。
- 原有 r、Shift+R、p/n、方向键、Ctrl+l、已读灰色和图标保留。
- 本轮未修改同步间隔、每次导入上限或分页游标算法。积压较大时的分页完整性属于后续独立修复，不要通过删号重加来排查网络。
- 公网 Quick Tunnel 换域名后，需要更新代理的精确域名规则；切换/重建 Clash 订阅也需检查本地增强文件关联。
